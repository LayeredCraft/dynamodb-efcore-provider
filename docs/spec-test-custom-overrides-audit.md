# EF Core Specification Custom Override Audit

This matrix started as an audit of executable specification-test overrides whose bodies did not
call the inherited EF Core base method. It now keeps the pre-refactor behavior separate from the
current disposition, so historical custom bodies are not described as current provider-specific spec
coverage after they have been thinned to `base` calls, `NoSyncTest` wrappers, or centralized skips.

Current dispositions:

- **Keep** — local body still exists because it is provider-specific infrastructure/guard behavior,
    not an upstream spec body to thin.
- **Delegated** — current override delegates to the inherited base method.
- **Delegated skip** — current override delegates to the inherited base method and skips with a
    centralized `SkipReason`.
- **Delegated/skipped** — current override delegates where supported and skips unsupported variants
    with centralized `SkipReason` values.
- **Delegated/sync guard** — supported async variants delegate to the inherited base method, while
    sync variants keep local assertions for async-only DynamoDB execution.
- **Accepted gap; delegated/skipped** — pre-refactor gap was accepted as non-required or represented
    elsewhere, and the spec override was thinned.
- **Needs decision** — do not refactor until the coverage gap is closed or explicitly accepted.

## Type equality overrides

These custom bodies were thinned in this PR. Current `Types/Dynamo*TypeTest.cs` classes
delegate the inherited equality query methods to the EF Core base implementation and skip them with
`SkipReason.QueryShapeNotSupported` because the EF10/EF11 upstream query shapes do not currently run
against the DynamoDB type-test fixtures. No replacement integration matrix was added in this PR;
existing integration tests provide representative scalar equality/type-mapping coverage only.
